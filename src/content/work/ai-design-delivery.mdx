## The cost of interpreting it again

Which component is this? What happens in an empty state? Does the layout change in Arabic? A handoff can be full of small questions that ask people to reconstruct decisions already made.

**The opportunity:** give AI-assisted implementation the context of an existing design system, then put review inside the workflow.

This sample story develops the Code Connect, knowledge-repository and content-pipeline practice described on the About page. The artifacts are illustrative until replaced with approved internal examples.

## Give the system something to work with

The proposed starting point is the system the team already maintains: component names, tokens, variants and behaviour. An implementation needs to fit that system, not merely resemble one screenshot.

The important connection is between **what the component means** and **how it behaves**. A good example would follow one component through its default, empty, error and bilingual states.

## Fast drafts still need slow questions

Does the interaction make sense? Can someone use it with a keyboard? What happens when the expected data never arrives?

AI can assist with scaffolding and repetitive changes. The designer and engineering partners remain responsible for choosing the interaction, checking the implementation and deciding whether it fits the product.

<StoryMedia caption="Proposed review checkpoints · these are responsibilities to demonstrate with actual project evidence.">

## Make the improvement travel

A useful internal tool should be usable by someone who did not build it. Show the inputs it expects, the output it produces, and the route back to a person when it fails.

For the leadership chapter, follow one adoption obstacle: a working session, a colleague’s question, or a change to the review process. Explain what you owned and what your partners contributed.

> The most interesting output is a capability the team can use again.

## Measure the whole journey

Time saved on a first draft is only part of the story. A fair comparison includes context preparation, correction, review and maintenance.
